Reviews now rate severity on a calibrated scale, propose their fixes as GitHub suggested changes, and keep their data for analysis.

- **Severity:**
  - Each finding has an impact from 0 to 10, anchored from "only matters for a cosmic-ray bit flip" to "the app would not work". It also has a likelihood (common, occasional or rare) and the trigger that makes it happen.
  - Severity follows from impact: Blocker 8–10, Major 5–7, Minor 0–4.
  - Below Blocker, a fix that removes non-test lines moves the finding up a level, and a fix the reviewer rates less readable moves it down two, as far as Nit.
- **Suggested changes:** reviewers propose the exact edit for each finding. Edits within the PR's diff are posted as one-click suggestions, and the review body shows every change as a diff.
- **Review data:**
  - Every review is recorded with its findings and the reviewer's ratings.
  - `local-autoreviewer triage` records what you did about a finding, and `findings --json` exports it all.
  - Reviews saved before this version are imported by housekeeping, and an expired job keeps its review output.
- **`local-autoreviewer review` owns its jobs** and never leaves them for the worker:
  - It waits out short retries and honours pushes and closes.
  - It cancels its unfinished jobs on any exit. A cancelled `--post` run hands the commit back to the service.
- **Posting:**
  - A failed post is retried from the saved review without running the agent again, and a post that reached GitHub despite an error isn't posted twice.
  - A definite refusal fails at once, while rate limits are retried.
  - Nothing is posted to a PR that was retargeted.
- **Polling:** GitHub is no longer called while the database write lock is held, and polls and `enqueue` run one at a time.
- **`local-autoreviewer --version`** prints the installed version.

The database gains two migrations. Upgrade while no `local-autoreviewer review` command is running; the worker restarts itself on the new version once it is idle.
