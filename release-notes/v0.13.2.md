Large PRs are measured by what the reviewer reads, and are noted once.

- **Deleted files show only their header** in `pr.diff` and `since-review.diff` (`git diff --irreversible-delete`). Reviewers with a shell can `git show` the old content by the blob ID on the diff's `index` line, and the prompts say how. A PR that drops a vendored library no longer fills the diff with it.
- **The size limits count only what the diff shows.** `max_changed_files` counts the files the diff shows changes to, leaving out excluded and deleted files, and `max_diff_bytes` measures the smaller diff. A follow-up's changes since the last review are measured the same way.
- **One "Automated review skipped" notice per PR:** a push that leaves a PR too large posts no further notice until a review of it has posted. The service checks the PR's own reviews under a lock per PR, so two reviewers of one commit post one notice, and a post whose answer was lost isn't repeated. In inline mode, excluded files are no longer embedded in the prompt either.
- **Forgejo inline comments span at most 50 lines.** Forgejo refuses every inline comment of a review if one spans more, so the review posted without them. A comment now marks at most the first 50 lines of a longer change, and shows the whole proposed diff when it fits in the comment.
