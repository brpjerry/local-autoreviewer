Reviews PRs on Forgejo servers as well as on GitHub (tested with Forgejo 17).

- **Forgejo repos:** name one with its host in the config, `name = "forge.example/owner/repo"`, and save an access token for that host in `~/.config/local-autoreviewer/forgejo-tokens/forge.example` (mode 0600; scopes *read:user*, *read:issue* and *write:repository*). Its PRs are polled, reviewed, followed up and asked for feedback like a GitHub repo's, and posted as the token's owner. `enqueue`, `review`, `findings` and `feedback` take `forge.example/owner/repo#N` or the PR's URL. `doctor` checks each host's token and repos.
- **What differs on Forgejo:** it has no suggested changes, so an inline comment shows its change as a diff and the body says the change is "also inline on the PR". Its API can't resolve a conversation, so a fixed finding's thread stays open. Links go to the file at the reviewed commit and to the commit itself.
- **The token** goes only to its own host: in the service's API requests, which ignore proxy settings and follow only a GET's redirect, and only to HTTPS on the same host, and in `git`'s environment as an `Authorization` header for that host, whose redirects git doesn't follow. It never reaches an agent, argv or a log, and a review that quotes it, or the header git sends, is blocked like one that quotes the GitHub token.
- **Token files** must hold the token alone, on one line; a file that doesn't, or can't be read, is reported without its contents. If the host can't be reached at startup, the owner last seen for the same token is used.
- **Pending drafts:** Forgejo submits the token owner's pending review on a PR together with the service's review. Use an account that doesn't keep review drafts on the PRs it reviews.
