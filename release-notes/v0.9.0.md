Any number of reviewers of each type, each with its own model.

- **More reviewers:** besides `claude` and `codex`, the config can add reviewers named `claude-<name>` or `codex-<name>`, such as `[agents.codex-sol]` with `model = "gpt-6.1-sol"`. Each one has its own model, effort and limits, and a repo lists it in `agents` like the others. The part before the first dash is its type. The type alone picks the CLI and its locked flags, and the config can't change that. All the reviews of a commit are still posted as one, with each reviewer named in it ("Codex and Codex sol"). Each reviewer has its own daily cap. Follow-ups carry on as before, because a round counts every reviewer of the PR.
- **One Codex review at a time:** the Codex reviewers share the reviews' one login, and two Codex processes refreshing its token at once can race. So the worker starts a Codex review only when no other Codex review is running, taking the oldest due one of any Codex reviewer. A hold that `tools/replay` takes on `codex` covers every Codex reviewer. Claude reviewers still run side by side.
- **Commands:** `review`, `enqueue` and `tools/replay` accept any configured reviewer with `--agent`. `doctor` checks each reviewer in use and names its model. If a reviewer is removed from the config, the worker doesn't start its queued reviews, and closing the PR clears them. `resume` and `ask` on its reviews say it is no longer configured.
