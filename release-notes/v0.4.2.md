Tunes the review prompts using the first feedback on posted reviews: 65 items on 13 PRs, 25 of the 27 reviews they answer ran on the prompts this replaces.

- **Proposed fixes:** before writing a fix, a reviewer now finds every path that sets, clears or reads the state it changes, and checks what the fix does on each one. Five proposed fixes on four PRs were wrong or incomplete, and two of them would have shipped broken if applied as written: one cleared the state in only one of two overloads, one set an option that another setting overrides. When a fix depends on runtime behaviour the code doesn't show, the reviewer says what to check.
- **Requirements:** a reviewer now checks what a change newly needs to run (a library feature or version, a platform, hardware), in full reviews and follow-ups. On three PRs a change came to rely on one. One review missed it; the other two raised it only as a question, which the author then had to check.
- **Test gaps:** a reviewer reads the existing tests before reporting a gap, and reports one only where the test is worth its cost. Feedback marked one test gap as a false positive and several as not worth writing.
- **Claims:** the description's and commit messages' claims about the code (a bug's cause, a measurement, a fix) are to be checked, not taken as given. A follow-up checks a fix against the finding, not against the commit message.

The prompt versions change, so the new reviews can be told apart from the old ones in the review data.
