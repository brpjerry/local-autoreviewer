Reviews leave you a reserve of each plan's usage limits.

- **Plan reserve:** before a review starts, the service reads its agent's plan usage limits. If any of them has less than `min_limit_left` percent left (new `[service]` setting, 10 by default; 0 turns the check off), the review is skipped: nothing runs or posts for it, the job ends `skipped` with the limit and its reset time in the reason, and the other reviewers' reviews of that commit post without it. A skipped review doesn't count towards `max_reviews_per_day`. A later push is checked again. A limit on one model only, such as Claude's weekly Fable limit, counts only for a reviewer running that model.
- **Where the limits come from**, as the agents' own usage displays read them:
  - Claude: the usage endpoint behind `/usage`, with your Claude login's access token, which is never refreshed;
  - Codex: `account/rateLimits/read` on a short-lived `codex app-server` in the reviews' `CODEX_HOME`, which starts no thread;
  - OpenCode: `opencode api --standalone get /api/experimental/usage/limits` in the reviews' home, for OpenCode Go's meters and budgets, which count only for reviewers on Go models (`opencode-go/…`). Free models report none.
- **Fail open:** a reading is kept for 10 minutes per login, and one that fails (offline, rate limited, an expired Claude token, or anything unexpected) lets the review run; a usage-limit error from the agent still defers it as before.
- **`doctor`** shows each reviewer's limits, and warns when one is under the reserve.
