Reviews leave you a reserve of each plan's usage limits.

- **Plan reserve:** before a review starts, the service reads its agent's plan usage limits. If any of them has less than `min_limit_left` percent left (new `[service]` setting, 10 by default; 0 turns the check off), the review is skipped: nothing runs or posts for it, the job ends `skipped` with the limit and its reset time in the reason, and the other reviewers' reviews of that commit post without it. A later push is checked again. A limit on one model only, such as Claude's weekly Fable limit, counts only for a reviewer running that model.
- **Where the limits come from**, as the agents' own usage displays read them:
  - Claude: the usage endpoint behind `/usage`, with your Claude login's access token, which is never refreshed;
  - Codex: `account/rateLimits/read` on a short-lived `codex app-server` in the reviews' `CODEX_HOME`, which starts no thread;
  - OpenCode: `opencode api --standalone get /api/experimental/usage/limits` in the reviews' home, for OpenCode Go's meters and budgets, which count only for reviewers on Go models (`opencode-go/…`). Free models report none.
- **A used-up limit found by a review is a skip too:** a review whose agent says a limit is used up ("usage limit reached", a quota, a free tier's limit, which is only seen this way) is skipped instead of deferred for 30 minutes, so the other reviewers' review of the commit doesn't wait out `combine_wait` for it. For the next 10 minutes the reviews of the same login and model are skipped without starting; those on its other models still run, as their quotas may be their own. A brief throttle ("rate limit exceeded", HTTP 429) is still deferred and retried, and so is any usage-limit error with `min_limit_left = 0`. A review skipped before its agent starts doesn't count towards `max_reviews_per_day`.
- **Fail open:** a reading is kept for 10 minutes per login, and one that fails (offline, rate limited, an expired Claude token, or anything unexpected) lets the review run.
- **`doctor`** shows each reviewer's limits, and warns when one is under the reserve.
