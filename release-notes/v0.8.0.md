Resolves the threads of fixed findings.

- **Resolved threads:** a fixed finding's inline suggestion stayed open on the PR, so the PR kept showing a suggestion the code no longer needed. The feedback on upscale-relay-android#64 pointed one out after the fix had landed. Now, once a follow-up is posted, the review threads of each previous finding that every reviewer of the round found fixed or obsolete are resolved. A finding's threads are the ones its own round posted for it: they belong to that round's review and carry its heading. A finding one reviewer found only partly fixed keeps its thread open. This holds whether the reviewers posted together or apart. While one of them is still running, nothing is resolved, and its own post decides. Two findings with the same title in one review share a heading, so their threads are resolved only once both are done. A follow-up whose post was confirmed after a timeout or a crash resolves its threads too.
- **GitHub:** this uses the GraphQL `resolveReviewThread` mutation, which the token's existing *Pull requests: read and write* permission covers. If GitHub refuses or fails, or anything else goes wrong, the threads stay open and the worker logs a warning. The review is already posted by then, and nothing that happens while resolving can post it again.
