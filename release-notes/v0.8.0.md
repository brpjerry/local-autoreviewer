Resolves the threads of fixed findings.

- **Resolved threads:** a fixed finding's inline suggestion stayed open on the PR, so the PR kept showing a suggestion the code no longer needed. The feedback on upscale-relay-android#64 pointed one out after the fix had landed. Now each posted follow-up sweeps the PR. It resolves the open threads of every finding that is closed: the latest commit that answered the finding has every posted reviewer's answer recorded, and all of them fixed or obsolete. That's the same rule by which the next follow-up stops asking about a finding. A finding one reviewer found only partly fixed keeps its thread open, whether the reviewers posted together or apart. While a review of the commit is still running, nothing is resolved. Its own post decides, or its end if it never posts, or the next round. Two findings with the same title in one review share a heading, which is resolved once both are closed, even in different rounds. A post confirmed after a timeout resolves threads too, unless the PR has moved on to another commit by then.
- **GitHub:** this uses the GraphQL `resolveReviewThread` mutation, which the token's existing *Pull requests: read and write* permission covers. If GitHub refuses or fails, or anything else goes wrong, the threads stay open and the worker logs a warning. The review is already posted by then, and nothing that happens while resolving can post it again.
