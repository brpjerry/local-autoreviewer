Codex reviewers now run side by side, like Claude's.

- **Codex reviewers run side by side:** 0.9.0 started a Codex review only when no other was running. Its reason was wrong: Codex processes that share one `auth.json` take turns refreshing it (Codex keeps an `auth.lock` beside it), and concurrent sessions on one login work. Only a *copy* of an `auth.json` in a second home races the original for the rotating refresh token, and the reviews never copy one: every Codex reviewer uses the reviews' own `CODEX_HOME` and its own login. So each reviewer now runs its own reviews, whatever else is running, and the reviews of a commit finish sooner. The README and `docs/agent-cli-notes.md` now say which sharing is safe.
- **`tools/replay` leaves the service alone:** it no longer refuses to start while the service runs a Codex review, or holds the service's Codex reviews while it runs. It shares the reviews' `CODEX_HOME` through a link, not a copy. Holds remain for `tools/live`, and a hold that names a type still holds all its reviewers.
- **A cancelled duplicate check is logged at INFO:** a push, `cancel` or stop during the check is an expected end, which the job's outcome already reports (for example `superseded`). It was logged as a WARNING. A check that times out, fails or hits a usage limit still logs a WARNING.
