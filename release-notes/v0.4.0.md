Every review now asks for feedback on itself, and the feedback is collected when the PR closes, for tuning the review prompts.

- **The request:** each posted review, full or follow-up, ends by asking for a PR comment that starts with **Review feedback**: what was useful, wrong or not worth fixing (findings by number), and what the review missed. Replies to its inline suggestions count too.
- **Collection:** when a reviewed PR closes, merged or not, the next poll collects the following, and does so once more a day later for feedback given after the merge:
  - PR comments, and PR reviews other than the service's own, with a line that starts with `Review feedback` (also as a heading or in bold, so a first line such as `From: …` is fine);
  - every reply in the thread of one of the review's inline suggestions;
  - other inline comments with such a line.

  Each item is tied to the review it answers. Each collection replaces the PR's previous one, so feedback deleted or untagged in the meantime goes. A collection that fails is retried by the next polls, up to 5 times, and a PR that is reopened and closed again is collected again. PRs that closed before this release are collected too, a few per poll, and so are PRs reviewed by hand that closed before a poll saw them.
- **`local-autoreviewer feedback [owner/repo#N] [--collect] [--json]`** lists the feedback. `--json` exports each item with the review it answers: its jobs (agent, model, effort, prompt version) and the file that holds the review as posted. `--collect` fetches it from GitHub first: one PR now, open or not, or every closed PR whose collection is due. It exits with status 1 if a collection failed.

No new token permission is needed: *Pull requests: read* covers the PR's comments. The database gains one migration. Upgrade while no `local-autoreviewer review` command is running; the worker restarts itself on the new version once it is idle.
