The worker picks up a replaced token without a restart.

- **Token files** (`github-token` and each `forgejo-tokens/<host>`) are read again whenever they change: replaced, rewritten or given a new mode. The next `gh` call, Forgejo request or `git` fetch uses the new token, including those of a review already running; a Forgejo listing already being read finishes its pages with the token it started with. The check that no review quotes a token knows the old token and the new one, and any token it found in a file it refused, or saw in the Forgejo token directory before.
- **An unusable change**, such as a file left readable by others, still empty or gone, keeps the token read before. The error is logged once, without the file's contents, and the worker switches once the file is fixed (a `chmod 600` is enough). The README shows how to replace a token in one step (`install` a new file, then `mv` it over the old one).
- **Token files are read through one open file**, which must be a regular file: its mode is checked on the file the token came from, and a FIFO in its place fails at once instead of blocking.
- **A token for another account** still needs the worker stopped while the file is replaced, because the account reviews post as is looked up at startup.
